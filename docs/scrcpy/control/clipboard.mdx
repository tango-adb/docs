# Set Clipboard

## Options

```ts
interface ScrcpySetClipboardControlMessage {
    sequence?: bigint;
    paste: boolean;
    content: string;
}
```

- `sequence`: <Version until="v1.20">Ignored.</Version> <Version since="v1.21">A sequence number for acknowledgment. When set to a non-zero value, the function returns a Promise that resolves when the device acknowledges the clipboard change. Set to `0n` to disable acknowledgment.</Version>
- `paste`: <Version until="v1.20">Ignored.</Version> <Version since="v1.21">Whether to trigger a paste action after setting the clipboard content.</Version>
- `content`: The text content to set in the clipboard.

## Usage

```ts transpile
// Using `ScrcpyControlMessageSerializer`
const message: Uint8Array = serializer.setClipboard({
    content: "Hello, world!",
    paste: false,
    sequence: 1n,
});

// Using `ScrcpyControlMessageWriter`
await writer.setClipboard({
    content: "Hello, world!",
    paste: false,
    sequence: 1n,
});

// Using `AdbScrcpyClient`
await client.controller!.setClipboard({
    content: "Hello, world!",
    paste: false,
    sequence: 1n,
});
```

### Clipboard acknowledgments

Set `sequence` to a non-zero value when the application needs confirmation that the Android device changed its clipboard:

- `sequence: 0n` sends the message without waiting for an acknowledgment.
- A non-zero sequence makes `setClipboard` return a Promise that resolves only after the device sends a matching acknowledgment.

The Promise may take slightly longer to resolve with a non-zero sequence. With `sequence: 0n`, it resolves immediately after sending the message.

```ts transpile
// Immediate return without waiting for device acknowledgment
await client.controller!.setClipboard({
    content: "Quick paste",
    paste: true,
    sequence: 0n,
});

// Wait for device acknowledgment before resolving
const resultPromise = client.controller!.setClipboard({
    content: "Confirmed paste",
    paste: true,
    sequence: 1n,
});

// resultPromise will resolve when device acknowledges the operation
await resultPromise;
```

This is commonly used to implement a paste operation. To change the clipboard before simulating `Ctrl+V`, set `paste: false`, use a non-zero sequence, await the acknowledgment, and then inject the paste shortcut:

```ts transpile
import {
    AndroidKeyCode,
    AndroidKeyEventMeta,
    ScrcpyControlMessageWriter,
} from "@yume-chan/scrcpy";

declare const controller: ScrcpyControlMessageWriter;

await controller.setClipboard({
    content: "Text to paste",
    paste: false,
    sequence: 1n,
});

// The device clipboard is confirmed to contain the text.
await controller.injectKeyDown({
    keyCode: AndroidKeyCode.KeyV,
    repeat: 0,
    metaState: AndroidKeyEventMeta.Ctrl,
});
await controller.injectKeyUp({
    keyCode: AndroidKeyCode.KeyV,
    repeat: 0,
    metaState: AndroidKeyEventMeta.Ctrl,
});
```

The `paste` field may perform the paste operation for you. Set `paste: true` when normal keyboard injection is available and no explicit confirmation is needed:

```ts transpile
import { ScrcpyControlMessageWriter } from "@yume-chan/scrcpy";

declare const controller: ScrcpyControlMessageWriter;

await controller.setClipboard({
    content: "Text to paste",
    paste: true,
    sequence: 0n,
});
```

UHID keyboards do not use ordinary Android key injection for the paste shortcut. In UHID keyboard mode, set the text with `paste: false`, wait for acknowledgment, and then send the appropriate UHID input report. This prevents the `Ctrl+V` report from being sent before the device accepts the new clipboard content.

Do not reuse an active sequence number for overlapping calls. Each non-zero sequence should identify one pending acknowledgment. The Promise rejects if the control socket closes or reports an error before the matching acknowledgment arrives.

The control socket must be enabled to receive acknowledgments. See [Connect to server](../connect-server.mdx#sockets) for the socket setup.
